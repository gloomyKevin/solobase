# Solo Product 项目规划文档 v1.0

> 中文世界最有品味的个人产品发现平台
> "帮你在信息洪流中找到最值得关注的个人产品"
> 
> 更新时间：2026-04-08

---

## 一、项目定位

### 1.1 一句话定义

一个以高品质内容策展 + 结构化项目数据库为核心的产品发现平台，面向所有"自己动手把想法变成产品"的人。

### 1.2 核心价值主张

在注意力稀缺的时代，人们需要的不是更多信息，而是一个值得信任的过滤器。本平台就是那个过滤器——帮用户从海量噪音中找到真正值得花时间了解的项目和洞察。

### 1.3 目标用户

不限于传统程序员，包括：

- 有技术背景的独立开发者
- 用 AI 工具（Cursor / Claude Code / Bolt / v0 等）构建产品的 Vibe Coder
- 产品经理、设计师、运营转创业者
- 完全非技术背景但用 AI 做产品的创作者

核心共性：一个人或极小团队，在做自己的产品。

### 1.4 用户画像（用于选品评估）

- **画像 A**：想做副业的程序员，有技术能力但不知道做什么，需要灵感和赛道判断
- **画像 B**：没有技术背景但想用 AI 做产品的人，需要可参考的路径和案例
- **画像 C**：已经有产品但卡在获客阶段的创始人，需要实战获客经验

每个候选项目至少要命中一个画像才值得收录。

### 1.5 竞品分析

| 竞品 | 形态 | 问题 | 我们的差异 |
|------|------|------|-----------|
| Indie Hackers | 英文社区 + 数据库 + 付费 Case Study | 中文用户门槛高，不贴合国内语境 | 中文原生，面向全球项目但用中文用户视角策展 |
| 即刻 | 社交信息流 | 内容转瞬即逝，无结构化沉淀 | 结构化项目卡片，永久可搜索可筛选 |
| w2solo | 传统论坛 | 活跃度极低，设计粗糙 | 高审美、策展驱动、品味作为核心壁垒 |
| 独立开发很酷 | 社区 | SEO 软文驱动，质量参差 | 内容质量为先，编辑把关 |
| Product Hunt | 英文产品发布平台 | 越来越水，中文产品边缘化 | 不做发布平台，做发现和策展 |

### 1.6 项目来源范围

不限于国内项目。标准是"对中文世界的 maker 有参考价值"——全球有意思的个人产品都在收录范围内。海外项目由 AI 辅助翻译和本地化语境解读。

## 二、产品架构

### 2.1 核心双引擎

**引擎一：内容策展（流量引擎 + 品牌基础）**

精选优质个人/小团队产品，写成有洞察的推荐和深度拆解。每条推荐的核心不是介绍产品功能，而是提供一个让人有收获的洞察——"这个人做对了什么"或"这个赛道的机会在哪"。

**引擎二：结构化项目库（数据资产 + 用户留存）**

每个被推荐的产品沉淀为标准化卡片，用户可浏览、筛选、发现。创始人可提交和认领项目。数据越积越厚，越积越有价值。

两者关系：内容策展在前面拉流量和建品牌，项目库在后面做沉淀和留存。

### 2.2 分类体系

#### 主分类维度（围绕用户决策，不随技术变化过时）

**按商业模式：** 订阅制（SaaS）/ 一次性付费 / 免费增值 / 广告变现 / 交易抽佣 / 开源+付费服务 / 内容付费

**按构建门槛：** 周末项目（几天）/ 月度项目（几周到一两个月）/ 持续工程（长期迭代）

**按增长方式：** SEO 驱动 / 社区口碑 / 内容营销 / 付费投放 / 产品自传播（Viral/PLG）

**按创始人画像：** 技术转产品 / 设计师做产品 / 产品经理做产品 / 非技术用AI构建 / 小团队合作

**按产品阶段：** Idea / Building / Launched / Revenue / Scaling

#### 辅助 Tag（可筛选但非主导航）

赛道标签、工具标签、技术栈标签、市场标签等。快速变化的维度（AI 工具、技术栈）全部做 tag 处理。

### 2.3 项目卡片设计

#### 列表态（Gallery 浏览）
产品名 + Logo + 一句话描述 + 截图预览 + 赛道标签 + 阶段标签 + 一个关键数据点

#### 详情态（展开）
完整介绍 + 多张截图 + 全部分类和标签 + Build Story（可选）+ 关键数据 + 外部链接 + 衍生机会观察 + 互动区域

### 2.4 投稿体系

#### 自荐（创始人提交自己的产品）

三层展示分级：

1. **基础卡片**：提交后自动入库，可搜索可筛选，不在首页展示。最低门槛：URL 必须可达，非 coming soon。
2. **精选**：通过编辑审核，进入首页展示。
3. **Featured Story**：编辑深度拆解，最高级别。

默认浏览只展示精选项目，基础卡片需用户主动切换"查看全部"。

MVP 提交表单极简字段：产品名（必填）、产品 URL（必填，自动验证）、一句话描述（必填）、赛道（下拉）、当前阶段（下拉）。其余可选，后续补充。

#### 他荐（用户推荐别人的产品）

用户提交 URL + 一句推荐理由。不自动公开，进入"待认领"队列，通知创始人确认后才公开。防刷：限每人每周推荐数量。

#### 里程碑更新（第二阶段）

定义关键里程碑节点，创始人到达时触发结构化更新。为 Radar 提供数据源。

### 2.5 Idea 处理

不单独设立 Idea 板块。Idea 作为项目卡片的衍生内容自然呈现。

原则：只展示事实性观察（"同赛道已收录 X 个项目，Y 个面向英文市场"），不做机会判断。标注数据来源。让用户自行得出结论。内部人机协作可用 AI 分析，但面向用户不做过强引导。

数据量 200+ 后可加聚合视图。

### 2.6 用户账号与互动

- 纯浏览：无需登录
- 收藏 / 关注赛道 / 订阅更新：需登录
- 提交 / 认领项目：需登录
- 反馈通道：结构化反馈入口，AI 友好（可直接接入 AI 处理分析）

注册钩子：关注某赛道，有新精选项目时通知。

## 三、技术方案

### 3.1 技术栈

- 前端：Next.js + TailwindCSS + Shadcn/ui
- 部署：Vercel（海外）+ 国内服务器（备案后）
- 数据库：MVP 本地 JSON/SQLite → 后期 Supabase (PostgreSQL)
- AI 工具链：Claude Team (Opus 4.6) 做开发，OneAPI 中转做内容自动化
- 自动化：脚本 + API 优先，受阻降级半自动/人工

### 3.2 端优先级

1. Web 响应式（MVP 唯一端）
2. iOS（后续视移动端流量决定，优先考虑 PWA）
3. 小程序（更后期）

### 3.3 备案策略

海外域名（.com）立刻上线 Vercel。国内域名走备案，保持未解析。备案通过后两域名并行运行。

### 3.4 MVP 数据模型

```
Project {
  id, name, url, tagline, description, screenshot_url,
  category_business_model,
  category_build_effort,
  category_growth_channel,
  category_founder_type,
  stage,
  tags[],
  revenue_range,
  launched_date,
  founder_id,
  status: draft | basic | featured | story,
  build_story,
  derived_insights[],
  submitted_by,
  created_at, updated_at
}

Founder {
  id, name, avatar, bio,
```

## 四、人机协作工作流

### 4.1 总体原则

AI 最大化优先，遇阻降级增加人工。内部可充分使用 AI 分析打分，面向用户不做过强 AI 引导。

### 4.2 信息源

**国内：** 即刻（RSSHub）、V2EX、小红书（手动+AI处理）、GitHub 列表

**海外：** Product Hunt（GraphQL API）、Indie Hackers（RSS尝试）、Twitter/X（手动+AI）

起步先做即刻 + Product Hunt，跑通后扩展。

### 4.3 每日工作流（目标 45-60 分钟）

| 步骤 | 谁做 | 时间 | 说明 |
|------|------|------|------|
| 扫描信息源 | 自动脚本 | 0 | RSS/API 优先，受阻降级 |
| AI 初筛打分 | AI (OneAPI) | 0 | 三个用户画像分别打分，保留达标项 |
| 最终选品 | 你 | 15-20min | 浏览候选列表，挑 1-2 个 |
| AI 生成草稿 | AI + 你 | 5-10min | 你给角度，AI 生成即刻版+小红书版+卡片数据 |
| 审核润色发布 | 你 | 20-30min | 确保品味印记，发布两平台 |

### 4.4 AI 评分标准建立

第一周完全手动选品，记录选择/拒绝案例。一周后用案例作为 few-shot 示例写进 prompt。持续用新决策更新标准。

### 4.5 小红书卡片模板

提前设计 2-3 套高品质图文模板，之后每天只换内容。设计品质是小红书差异化的核心。

## 五、冷启动策略

### 5.1 分发渠道

| 渠道 | 角色 | 内容形态 |
|------|------|----------|
| 即刻 | 主要转化（可放外链） | 深度推荐 + 产品链接 |
| 小红书 | 主要曝光（高流量） | 精美卡片图 + 精华文案 |
| SEO | 长期（3-6月起量） | 项目库页面自然排名 |
| AI 搜索收录 | 长期（结构化数据布局） | 利于 AI 抓取的数据结构 |

一鱼两吃：写完整版 → 即刻深度版 → 提取精华+卡片图 → 小红书视觉版。

### 5.2 冷启动数据

第一批 30 个项目由你主动筛选填充，不需创始人参与。从公开信息中找项目，自己体验，自己写卡片。选品质量 = 品牌宣言。

### 5.3 内容节奏

一周 3 条推荐，或"每周值得关注的 3 个产品"周更合集。

## 六、壁垒建设

- **短期**：选品品味 + 设计品质 → 品牌认知
- **中期**：结构化数据积累 → 后来者追不上
- **长期**：创始人认领 + 社区网络效应 → 迁移成本

---

## 七、变现路径（后期）

1. 深度 Featured Story 付费内容
2. 项目方付费推广位
3. 面向创始人群体的品牌广告
4. 高级数据筛选 / 趋势报告付费订阅
5. 付费咨询匹配

## 八、MVP 计划（4-5 天）

### 8.1 MVP 包含

- 高品质首页（精选项目展示）
- 项目卡片详情页
- 按维度浏览和筛选
- 创始人自荐提交表单（含 URL 验证）
- 他荐推荐表单
- 结构化反馈入口（AI 友好）
- 移动端响应式
- 数据本地存储（可迁移架构）
- Radar demo 页面（模拟数据）
- 公网可访问

### 8.2 MVP 不包含

用户登录系统、收藏/关注、里程碑更新、Radar 真实数据、Build Story 编辑器、全自动信息源扫描、iOS App、小程序

### 8.3 并行任务

- 产品视觉/交互/调性设计与开发（主线）
- 人机协作筛选工作流搭建（主线）
- 内容产出（每周 2-3 条，即刻+小红书）
- 备案申请提交
- 种子项目积累（目标 30 个）
- 与被推荐创始人沟通

### 8.4 MVP 里程碑

- [ ] 产品视觉调性确定
- [ ] 首页 + 卡片详情页 + 浏览筛选完成
- [ ] 提交表单（自荐+他荐）完成
- [ ] 反馈入口完成
- [ ] 小红书卡片模板完成（2-3套）
- [ ] 人机协作筛选工作流跑通
- [ ] 数据本地存储，可迁移架构
- [ ] 公网可访问（Vercel）
- [ ] 10+ 种子项目入库
- [ ] 2-3 条推荐内容已发布
- [ ] 备案已提交

### 8.5 止损标准

8 周内 MVP 上线并公开推广。12 周内达到 100+ 项目、1000+ 周活跃访客。未达到则复盘调整。

## 九、团队

- **你**：产品 CEO + 主编。品牌调性、选品决策、产品体验、核心审美、关键架构
- **弟弟**（远程兼职）：数据录入、校验、执行
- **AI 工具链**：内容生产、扫描、初筛、草稿、翻译
- **华为朋友**（偶尔咨询）：技术 sense check

## 十、关键风险

| 风险 | 应对 |
|------|------|
| 冷启动无人来 | 先做内容建品牌，不做空平台等人 |
| 信息源防爬 | AI 优先，受阻降级，优先 RSS/API |
| 内容质量不稳定 | 选品始终你亲自把关 |
| 被复制 | 品味和品牌认知是壁垒，速度 > 保密 |
| 备案延迟 | 双域名策略 |
| AI 幻觉 | 面向用户只展示事实，不做强判断 |
| 坚持不下来 | 12 周止损线 |
| 功能贪多 | 严格 MVP 定义 |
